### Width and overflow controls already present

- The global reset applies `box-sizing: border-box` and `img { max-width: 100% }`, reducing common overflow causes (`css/shared.css:100-118`).
- Main containers use `width: min(100%, 1440px)` with responsive gutters (`css/shared.css:32-33`, `css/shared.css:581-585`).
- Major grids increasingly use `minmax(0, 1fr)`, including admin, account, checkout, dashboard KPIs, services, and recent home-page sections.
- Admin content and cards explicitly use `min-width: 0`; admin tabs and shared tables use local horizontal scrolling rather than forcing page width.
- These safeguards reduce risk but do not invalidate the breakpoint-edge and dynamically generated navigation findings above.

### Accessibility and i18n initialization

- Every HTML page links `js/accesibilidad.js`. It initializes theme, font scale, and accessibility controls once through either `DOMContentLoaded` or immediate execution (`js/accesibilidad.js:98-133`).
- The same file unconditionally calls `import("./i18n.js")` (`js/accesibilidad.js:145`). Therefore all 24 pages have a local i18n loading path even when the HTML does not link `i18n.js` directly.
- All 9 administrative pages additionally include `<script type="module" src="../js/i18n.js">` immediately after `accesibilidad.js`. Two loading paths to the same resolved module URL are therefore **confirmed** in their markup/code.
- A duplicated `initI18n()` execution is **not confirmed by the code**. Both paths target the same ES module URL, and the module has no explicit second-init guard; browser module-map behavior must be observed if duplicate network/init behavior is suspected. Runtime/network verification is **pending**.
- `i18n.js` initializes immediately, loads one of four JSON dictionaries, creates the local language selector, applies translations, and emits `waypath:languagechange` (`js/i18n.js:17-20`, `45-98`, `101-113`).
- The Google callback only creates Google Translate when `window.WayPathI18n` is absent (`js/accesibilidad.js:135-143`). Because local i18n is loaded asynchronously, which translation UI wins is timing-dependent in source terms. The actual runtime outcome is **pending**.

### Confirmed system inconsistencies

- The token layer contains aliases for the same concepts (`--blue-*` plus `--brand-primary*` plus `--primary-blue`; `--text-*` plus `--text-primary/secondary/muted`; `--border` plus `--border-color`). They currently map coherently, but broaden the API and allow pages to choose different naming conventions.
- Radius usage is not component-stable: shared cards use `--radius-sm`, dashboard cards use `--radius-md`/`--radius-lg`, contact cards use `--radius-lg`, and landing cards use `--radius-lg`.
- Page-specific icon accents repeatedly hard-code purple, cyan, yellow, and green values inline rather than defining semantic/accent tokens.
- The global system supports light/dark themes, font scaling, focus rings, reduced motion, common buttons, badges, alerts, status pills, cards, tables, inputs, header, and footer; login partially bypasses that system.
- The audit has not yet established computed styles, contrast ratios, actual viewport overflow, font-loading behavior, or pixel-level visual consistency. Those checks remain **Pending** until the web is executed in the visual, responsive, and accessibility phases.
